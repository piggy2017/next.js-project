# 2026-10-13

## feature/sl/i18next 回退合并后的分叉，以及 `git pull` 报错说明

### 现象
`git pull --tags origin feature/sl/i18next` 报：
`fatal: Need to specify how to reconcile divergent branches.`

### 根因：本地与远端已分叉（`ahead 1, behind 2`），共同祖先为 `0d5d566`

- 本地领先：`226c67f docs: 添加项目长期约定及主题系统的既定约定`——在回退基线 `0d5d566` 之上新增，内容为 `.workbuddy/memory/2026-10-12.md` 与 `MEMORY.md`（共 63 行新增）。
- 远端领先：`c6d0091`（dev-theme 的主题切换重构）、`38b7624`（`Merge branch 'feature/dev-theme' into feature/sl/i18next`）。
- 该分叉是「本地已回退到合并前、远端仍含合并提交」的**预期结果**，不是需要 pull 去修复的错误。

### 正确处置
不要用 git 提示的 `pull.rebase false/true` 或 `pull.ff only` 去「调和」：前两者会把合并提交重新并入分支，从而抵消回退；`pull.ff only` 只是拒绝合并，也不解决分叉。正解是**不 pull，直接强制推送**：

```
git push --force-with-lease origin feature/sl/i18next
```

推送后远端分支即为 `226c67f`，合并提交 `38b7624` 与 `c6d0091` 从该分支脱离（`c6d0091` 仍由 `feature/dev-theme` 引用，不会丢失）。

### 本会话环境边界
当前 agent 环境内无法完成推送，四次尝试均为 `git@github.com: Permission denied (publickey)`。排查结论：`ssh-agent` 无身份、macOS 钥匙串无身份、`~/.ssh/id_rsa` 与 `~/.ssh/id_rsa_new` 两把密钥均被 GitHub 拒绝、无 `gh` CLI、无 credential helper 与凭据文件。推送须在用户自己的终端执行。

### 处置时的两个细节（本次实际踩到）
1. `git reset --hard` 会删除「HEAD 跟踪但目标提交中不存在」的文件——`.workbuddy/memory/*` 正属此类，回退时会被删掉，已先备份至 `/tmp/wb-memory-backup` 再复原。
2. 回退后若执行了一次 `git pull`，快进会把合并提交拉回来、使回退失效（本次已发生一次），因此回退与强制推送应连续完成。

### 恢复引用
本地分支 `backup/merge-i18next-38b7624` → `38b7624`；远端在 force-push 前仍持有该提交。
